# US-017: Mode sombre interface admin et formulaire candidat

**Status:** 🔲 Backlog  
**Milestone:** Epic 4 — Could Have & Should Have  
**GitHub Issue:** [#17](https://github.com/Paro-fds/bravetech/issues/17)  
**Depends on:** Epic 3 terminé (interface admin stable)

---

## En tant que candidat / administrateur FDS
Je veux pouvoir basculer l'interface en mode sombre  
Afin de réduire la fatigue visuelle lors d'une utilisation prolongée, en particulier sur mobile.

## Critères d'acceptation
- [x] Un bouton de basculement (icône soleil/lune) est accessible depuis la barre de navigation principale et depuis le dashboard admin.
- [x] Le thème (clair/sombre) est persisté dans `localStorage` et restauré au rechargement de la page.
- [x] Le mode sombre est implémenté via `[data-theme="dark"]` sur la balise `<html>`, sans librairie externe.
- [x] Toutes les couleurs de l'interface utilisent des variables CSS centralisées — le changement de thème ne nécessite aucune modification de composant.
- [x] Les contrastes du mode sombre respectent WCAG 2.1 AA (ratio ≥ 4.5:1 pour le texte normal).
- [x] La préférence système (`prefers-color-scheme`) est détectée au premier chargement si aucune préférence n'est enregistrée.

## Hors périmètre
- Thème personnalisable (couleurs custom) — hors MVP.
- Mode sombre sur les emails transactionnels.

## Tâches
- [x] Définir les variables CSS pour les deux thèmes dans `index.css` (couleurs, surfaces, textes)
- [x] Implémenter le hook `useTheme()` pour gérer la persistance `localStorage` (+ script anti-éclair dans `index.html`)
- [x] Ajouter le bouton de basculement dans le composant `Navbar` et le `AdminLayout` (le `Navbar` n'existe plus depuis US-021 : bouton placé dans `SiteLayout`, `FlowLayout` et `AdminLayout`)
- [x] Tester les contrastes sur les pages critiques (formulaire candidature, dashboard admin, page suivi)

## Définition de fini
- [ ] Le basculement clair/sombre fonctionne sur toutes les pages. Le thème est mémorisé entre les sessions. Les contrastes WCAG AA sont respectés en mode sombre.

## As-built notes
**2026-11-02 — code écrit, rendu vérifié par captures d'écran Chrome (360 px et 1280 px), en clair et en sombre** (branche `feat/us-017-mode-sombre`, issue de `master` c9d93fb) :
- **Jetons de rôle** : `index.css` définit 30 couleurs `fds-*` nommées par rôle (page, surface, surface-alt, sunken, title, accent, ink, mute, line, field, ok/bad/warn et leurs fonds et traits, aplats navy/ok-solid/bad-solid, on-navy, on-light). Le mode sombre les redéfinit sous `:root[data-theme='dark']` (avec `color-scheme: dark` pour les champs natifs et les barres de défilement). Le thème clair est **inchangé à l'œil**, sauf la bordure des champs, foncée de `#8796b0` à `#8291ab` : elle était à 2,99:1, sous le minimum de 3:1 pour un bord de champ.
- **Migration des composants** (24 fichiers, remplacement mécanique) : `bg-white` → `bg-fds-surface`, `text-fds-navy(-d)` → `text-fds-accent` / `text-fds-title`, `border`/`ring-fds-navy` → `fds-accent`, couleurs `[#…]` → jetons, aplats verts et rouges à texte blanc → `*-solid`, barres de progression → `fds-accent` / `fds-ok` (visibles sur le rail dans les deux thèmes). Il ne reste **aucune couleur codée en dur** dans `src/` (hors `text-white` et `bg-white/10` sur aplat marine, voulus). La règle est consignée dans la spec technique WS-01 (R4).
- **Ce qui ne change pas de couleur** : les en-têtes, la barre latérale admin et le bandeau d'accueil restent des aplats marine (un peu éclaircis en sombre : `#1d4b86`) ; le bouton or « Postuler » garde son texte marine ; la pastille active FR/KR reste blanche.
- **Bandeau « PAIEMENT SIMULÉ »** : les hachures utilisent les jetons warn ; en sombre, elles sont ambre foncé avec un texte ambre clair (8,3:1), toujours aussi distinctes d'un vrai paiement (fait critique n° 8).
- **Bascule** : `shared/theme/` contient `theme.ts` (règles pures), `useTheme.ts` (store zustand) et `ThemeToggle.tsx` (bouton 44 px, lune ou soleil, interrupteur `aria-pressed` « Mode sombre » / « Mòd fènwa »). Le bouton est dans l'en-tête des pages publiques, du tunnel et du suivi, et dans la barre latérale admin (libellé fixe en français, l'administration n'étant pas traduite). Le login admin n'a pas de bouton mais suit le thème choisi.
- **Mémorisation et préférence système** : le choix est stocké dans `localStorage` (clé `fds-theme`, valeur brute `clair` ou `sombre`, sans erreur si le stockage est bloqué). Sans choix enregistré, le site suit `prefers-color-scheme`, y compris si le système change pendant la visite. Un court script en tête de `index.html` pose `data-theme` **avant** le premier affichage, ce qui évite un éclair blanc au chargement en mode sombre. Les anciennes classes `bg-slate-50…` du `<body>` et les variables `--primary…` inutilisées ont été retirées.
- **En-tête mobile** : avec le bouton de thème, la ligne du logo ne tenait plus à 360 px. Le nom passe donc sur deux lignes (« Faculté des / Sciences ») et la ligne « Université d'État d'Haïti » est masquée sous 400 px de large. Elle reste dans le pied de page et le texte du logo.
- **Contrastes WCAG 2.1 AA** : 30 paires texte/fond réellement utilisées, calculées pour les deux thèmes. Toutes passent : 4,5:1 ou plus pour le texte, 3:1 ou plus pour les bords de champ et les barres. Minimums en sombre : texte blanc sur bouton vert 5,34:1, bord de champ 4,35:1.
- **Tests** : `npm test` passe de 9 à 13 tests (choix enregistré prioritaire, repli sur le système, valeur invalide ignorée, `data-theme="dark"`). Pas de test de composant, faute de banc de test frontend.
- **Vérifié** : `tsc -b`, `oxlint`, `vite build`, `npm test`. Captures en clair et en sombre : accueil (360 et 1280 px), fiche MPC, étape 1 du tunnel, suivi d'un dossier, liste admin (1280 et 360 px), dossier admin. **Non vérifié à l'écran** : étapes 2 à 6 du tunnel (dont le bandeau de paiement en sombre, contrastes seulement calculés), Contact, Histoire, remplacement d'une pièce, page de connexion admin. Pas vérifié non plus dans un vrai navigateur : le clic sur le bouton, la mémorisation après rechargement et l'absence d'éclair blanc.
