# US-012: Dashboard admin — liste et consultation des candidatures

**Status:** 🔲 Backlog  
**Milestone:** Epic 3 — Administration & Audit  
**GitHub Issue:** [#12](https://github.com/Paro-fds/bravetech/issues/12)  
**Depends on:** US-011 (Auth admin), US-008 (Candidatures en base)

---

## En tant qu'administrateur FDS
Je veux accéder à un tableau de bord listant toutes les candidatures reçues avec leurs statuts  
Afin de piloter efficacement le traitement des dossiers et de suivre les indicateurs clés (dont `deplacement_physique`).

## Contexte
L'admin doit pouvoir consulter la liste paginée des dossiers, filtrer par statut ou cursus, ouvrir un dossier spécifique et voir le détail de chaque document soumis. La liste expose `deplacement_physique` pour permettre le suivi de l'hypothèse du §7 du CDC.

## Critères d'acceptation
- [ ] L'endpoint `GET /api/admin/candidatures?page=1&limit=20` retourne la liste paginée des candidatures (avec `total`, `page`, `limit`, `items`).
- [ ] Chaque item de la liste expose : `reference_dossier`, `nom`, `prenom`, `cursus_slug`, `statut_paiement`, `deplacement_physique`, `created_at`, et le nombre de documents `en_attente` / `valide` / `rejete`.
- [ ] L'endpoint `GET /api/admin/candidatures/{reference}` retourne le dossier complet avec la liste des `documents_soumis` et leurs statuts.
- [ ] Toutes ces routes retournent HTTP 401/403 si le JWT est absent ou invalide.
- [ ] Le frontend affiche le dashboard sur `/admin/dashboard` avec une table paginée et un lien vers la vue détaillée de chaque dossier.
- [ ] La vue détaillée d'un dossier liste chaque document avec son statut visuel (`en_attente`, `valide`, `rejete`) et un accès à son contenu via le proxy sécurisé.
- [ ] `GET /api/admin/proxy-document/{id}` retourne le fichier avec le bon `Content-Type` — accessible uniquement aux admins authentifiés (protection contre l'accès direct aux URLs de stockage).

## Hors périmètre
- La validation ou le rejet d'un document (US-013).
- Les statistiques et exports (Epic 4 — Could Have).

## Tâches
- [ ] Implémenter `GET /api/admin/candidatures` (paginé) et `GET /api/admin/candidatures/{reference}`
- [ ] Implémenter `GET /api/admin/proxy-document/{id}` (proxy sécurisé)
- [ ] Créer les pages React `/admin/dashboard` et `/admin/candidatures/{reference}`
- [ ] Écrire les tests d'intégration (accès protégé, pagination, détail dossier)

## Définition de fini
- [ ] Un admin authentifié peut consulter la liste paginée des dossiers et ouvrir un dossier complet avec la liste de ses documents. Un utilisateur non authentifié reçoit 401.
