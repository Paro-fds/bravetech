# US-004 — Déploiement en environnement accessible

**Statut :** 🔲 Backlog (reporté — après US-001 et US-002)
**Milestone :** Epic 1 — Socle & Portail public
**GitHub Issue :** [#4](https://github.com/Paro-fds/bravetech/issues/4)
**Dépend de :** US-001, US-002 (contenu stable avant de déployer)

---

## En tant que développeur
Je veux que le backend et le frontend soient accessibles depuis un environnement partagé (hors machine locale)
Afin que l'équipe et les premiers testeurs puissent valider le portail sans dépendre d'un serveur local.

## Contexte

US-001 et US-002 ont livré un portail fonctionnel localement. Cette story connecte l'environnement de déploiement cible.

**L'infrastructure de déploiement est à définir** — l'intention actuelle est un serveur Linux de la faculté accessible via Proxmox. La décision finale (architecture réseau, reverse proxy, gestionnaire de process) sera enregistrée dans `SOLUTION_DESIGN.md §14` (ADR-006) avant que cette story démarre.

Ce qu'il ne faut pas supposer déjà fait :
- L'infrastructure n'est pas encore provisionnée
- Les variables d'environnement de production ne sont pas encore configurées
- Cette story ne démarre qu'une fois US-001 et US-002 ✅ Done

## Critères d'acceptation

- [ ] Le backend FastAPI répond à `GET /api/v1/cursus` depuis l'URL de production (à définir)
- [ ] Le frontend est accessible depuis cette même URL ou un sous-domaine dédié
- [ ] La page d'accueil en production affiche les cursus réels (appel au backend de production)
- [ ] Toutes les variables d'environnement sensibles (`DATABASE_URL`, `SECRET_KEY`, etc.) sont configurées côté serveur — jamais dans le code versionné
- [ ] `.gitignore` inclut `.env`, `*.env`, `.env.*`
- [ ] `pytest tests/` reste vert après le déploiement

## Hors périmètre

- Le choix de l'infrastructure (Proxmox, VPS, PaaS) — à décider et enregistrer dans `SOLUTION_DESIGN.md` avant de démarrer cette story
- Domaine custom — à confirmer avec la faculté
- Monitoring et alertes automatiques — post-MVP

## Tâches

*(À détailler une fois l'infrastructure décidée — voir `epic-001-refinement.md` Q2 et Q4)*

- [ ] Enregistrer la décision d'infrastructure dans `SOLUTION_DESIGN.md §14` (ADR-006) avant de commencer
- [ ] Provisionner l'environnement cible (VM Proxmox, accès SSH, etc.)
- [ ] Configurer le reverse proxy (nginx ou équivalent) si nécessaire

- [ ] Déployer le backend (process manager à définir : systemd, supervisor, Docker…)

- [ ] `GET <url-production>/api/v1/cursus` → 200 avec données réelles
- [ ] Page d'accueil en production affiche les cursus
- [ ] Aucun secret dans le code versionné
- [ ] `pytest tests/` : 0 échec
- [ ] ADR-006 écrit dans `SOLUTION_DESIGN.md §14`
