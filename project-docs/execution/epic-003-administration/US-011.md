# US-011: Authentification de l'administrateur (JWT + RBAC)

**Status:** 🔲 Backlog  
**Milestone:** Epic 3 — Administration & Audit  
**GitHub Issue:** [#11](https://github.com/Paro-fds/bravetech/issues/11)

## En tant qu'administrateur FDS
Je veux devoir m'authentifier avec mes identifiants avant d'accéder au tableau de bord  
Afin d'empêcher tout accès non autorisé aux dossiers des candidats.

## Contexte
Le portail gère des données personnelles sensibles. Toutes les routes `/api/v1/admin/*` doivent être protégées. L'authentification repose sur email + mot de passe hashé (bcrypt), avec délivrance d'un JWT HS256 valable 60 minutes. Deux rôles existent : `admin` (accès complet) et `agent` (validation documents). Le rate limiting protège l'endpoint de connexion contre le brute-force (5 tentatives / 60 s par IP).

## Critères d'acceptation
- [ ] L'endpoint `POST /api/v1/auth/token` accepte `email` et `password`, valide le hash bcrypt et retourne un JWT signé HS256 (durée : 60 min).
- [ ] Un JWT invalide ou expiré sur une route admin retourne HTTP 401.
- [ ] Un JWT valide mais avec un rôle insuffisant retourne HTTP 403.
- [ ] Après 5 tentatives échouées en moins de 60 s depuis la même IP, l'endpoint retourne HTTP 429 (Too Many Requests).
- [ ] La page de connexion frontend (`/admin/login`) affiche un message d'erreur générique en cas d'échec (sans exposer les détails internes).
- [ ] Le secret JWT (≥ 256 bits) est chargé depuis une variable d'environnement — jamais en dur dans le code.
- [ ] Un script de seed crée le premier compte admin depuis `ADMIN_SEED_PASSWORD` (exécuté une seule fois au déploiement).

## Hors périmètre
- Refresh tokens (post-MVP).
- SSO institutionnel ou intégration FDS SYS (hors périmètre V1).
- Réinitialisation de mot de passe par email (post-MVP).

## As-built notes
**2026-11-01 — code écrit et vérifié sur un vrai serveur, à valider dans un navigateur** (branche `feat/us-011-auth-admin`, empilée sur US-009) :
- **Routes** : `POST /api/v1/auth/token` (corps JSON `email` + `password`, et non un formulaire OAuth2) et `GET /api/v1/admin/moi`. Le routeur `/admin` entier porte `get_current_admin` : une route ajoutée plus tard ne peut pas oublier la protection, et un test parcourt le schéma OpenAPI pour vérifier que toute route `/admin` refuse l'accès anonyme.
- **Rôles** : `get_current_admin` accepte `admin` et `agent` ; `get_current_admin_complet` n'accepte que `admin` (aucune route ne l'utilise encore, testé sur une mini-application). Le rôle et l'état actif sont **relus en base à chaque requête** : désactiver un compte ou changer son rôle s'applique tout de suite, sans attendre l'expiration du jeton.
- **Jeton** : JWT HS256, 60 minutes, sans renouvellement. L'algorithme est imposé au décodage (un jeton `alg: none`, sans expiration, expiré ou signé avec un autre secret est refusé, tests à l'appui).
- **Secret** : `JWT_SECRET`, 32 caractères minimum, **sans valeur par défaut**. Absent ou trop court → la connexion répond 503 et le journal le dit, plutôt que de signer avec un secret connu. Variable ajoutée à `docker-compose.yml` et `.env.example` ; à renseigner avant le premier démarrage en production.
- **Anti brute-force** : seuls les **échecs** comptent (5 par minute et par IP, puis 429 avec `Retry-After: 60`, même avec le bon mot de passe). Les connexions réussies ne sont pas limitées. Comme pour les autres limiteurs, le compteur est en mémoire d'un seul processus.
- **Pas de fuite** : email inconnu, mauvais mot de passe et compte désactivé donnent la même réponse 401 et le même travail de hachage bcrypt. Les mots de passe de plus de 72 octets (limite de bcrypt) sont refusés à la connexion.
- **Seed** : `docker compose exec backend python -m backend.scripts.seed_admin` avec `ADMIN_SEED_EMAIL` et `ADMIN_SEED_PASSWORD` (12 caractères minimum). Idempotent : relancé, il ne change rien si le compte existe. Le mot de passe n'apparaît ni dans les journaux ni à l'écran.
- **Interface** : `/admin/login` d'après la maquette (message d'erreur générique, 429 et 503 distingués) ; `/admin` est une page d'accueil provisoire protégée, avec « Se déconnecter » (US-012 la remplace par le tableau de bord). La session est gardée dans `sessionStorage` : elle disparaît à la fermeture de l'onglet, utile sur un poste partagé.
- **Hors de l'US, à décider** : il n'existe pas de création de comptes agents depuis l'interface ; seul le premier admin est créé par le script. Les agents devront être ajoutés par une autre voie (US à écrire).
- **Vérifié** : `pytest` (233 tests verts, dont `test_architecture.py`) ; parcours réel sur serveur lancé (seed deux fois, mot de passe court refusé, connexion, route protégée avec et sans jeton, 6 échecs → 429) ; `tsc -b` et `vite build` sans erreur. **Non vérifié** : la page de connexion dans un navigateur, l'expiration réelle après 60 minutes, Docker.
