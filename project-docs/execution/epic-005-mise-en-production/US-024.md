# US-024: Adresse réelle du visiteur derrière les proxys

## Contexte
`backend/api/v1/limiteur.py` limite la consultation de dossiers (20 requêtes, US-009) et les envois par adresse IP. `adresse_client` lit le **premier** élément de `X-Forwarded-For` (E5-7, [epic-005-refinement.md](epic-005-refinement.md)).

En production, la chaîne est : visiteur → Apache UEH (TLS) → Nginx du conteneur frontend → FastAPI. Deux défauts :
- le premier élément de `X-Forwarded-For` est fourni par le visiteur : il peut l'inventer et contourner le limiteur ;
- si l'Apache UEH ne transmet pas l'adresse du visiteur, tous les candidats partagent la même adresse et le limiteur bloque tout le monde après 20 consultations.

Workstream : WS-03 (suivi), transverse (`api/`, `frontend/nginx.conf`).

## Critères d'acceptation
- [ ] L'adresse retenue est celle ajoutée par le dernier proxy de confiance (lecture depuis la droite de `X-Forwarded-For`, nombre de proxys de confiance configurable par variable d'environnement).
- [ ] Un `X-Forwarded-For` inventé par le visiteur ne change pas l'adresse retenue (test).
- [ ] Sans proxy (développement), l'adresse de la connexion est utilisée.
- [ ] La configuration attendue de l'Apache UEH (en-têtes transmis) est écrite dans la spec tech, et vérifiée sur la VM une fois la bascule faite.

## Hors périmètre
- Un limiteur partagé entre plusieurs processus (Redis) : un seul processus uvicorn en V1.
