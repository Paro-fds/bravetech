# US-012: Dashboard admin — liste et consultation des candidatures

**Status:** ✅ Done  
**Milestone:** Epic 3 — Administration & Audit  
**GitHub Issue:** [#12](https://github.com/Paro-fds/bravetech/issues/12)  
**Depends on:** US-011 (Auth admin), US-008 (Candidatures en base)

---

## En tant qu'administrateur FDS
Je veux accéder à un tableau de bord listant toutes les candidatures reçues avec leurs statuts  
Afin de piloter efficacement le traitement des dossiers et de suivre les indicateurs clés (dont `deplacement_physique`).

## Contexte
L'admin doit pouvoir consulter la liste paginée des dossiers, filtrer par statut ou par déplacement physique, ouvrir un dossier spécifique et voir le détail de chaque document soumis. La liste expose `deplacement_physique` pour permettre le suivi de l'hypothèse du §7 du CDC.

## Critères d'acceptation
- [ ] L'endpoint `GET /api/v1/admin/candidatures?page=1&limit=20` retourne la liste paginée des candidatures (avec `total`, `page`, `limit`, `items`).
- [ ] Chaque item de la liste expose : `reference_dossier`, `nom`, `prenom`, `statut_paiement`, `deplacement_physique`, `created_at`, et le nombre de documents `en_attente` / `valide` / `rejete`.
- [ ] L'endpoint `GET /api/v1/admin/candidatures/{reference}` retourne le dossier complet avec la liste des `documents_soumis` et leurs statuts.
- [ ] Toutes ces routes retournent HTTP 401/403 si le JWT est absent ou invalide.
- [ ] Le frontend affiche le dashboard sur `/admin` (`/admin/dashboard` y redirige) avec une table paginée et un lien vers la vue détaillée de chaque dossier.
- [ ] La vue détaillée d'un dossier liste chaque document avec son statut visuel (`en_attente`, `valide`, `rejete`) et un accès à son contenu via le proxy sécurisé.
- [ ] `GET /api/v1/admin/proxy-document/{id}` retourne le fichier avec le bon `Content-Type` — accessible uniquement aux admins authentifiés (protection contre l'accès direct aux URLs de stockage).

## Hors périmètre
- La validation ou le rejet d'un document (US-013).
- Les statistiques et exports (Epic 4 — Could Have).

## As-built notes
**2026-11-01 — code écrit et vérifié côté API sur un vrai serveur, à valider dans un navigateur** (branche `feat/us-012-dashboard-admin`, empilée sur US-011) :
- **Routes** (toutes sous le routeur `/api/v1/admin`, donc protégées par `get_current_admin`) : `GET /candidatures?page&limit&q&statut&deplacement_physique`, `GET /candidatures/{reference}`, `GET /proxy-document/{document_id}`. Pages : `/admin` (liste, avec les indicateurs), `/admin/candidatures/:reference` (détail). Mise en page des maquettes `AdminListe` et `AdminDossier`, barre latérale comprise.
- **Seuls les dossiers soumis** apparaissent : un brouillon n'est pas un dossier, et son identifiant ne permet pas d'ouvrir un détail.
- **Statut d'un dossier** (même règle que le suivi du candidat) : *À examiner* ; *Action du candidat* dès qu'une pièce est refusée ; *Complet* quand les 5 pièces sont validées.
- **Indicateurs** (sur tous les dossiers soumis, indépendamment des filtres) : dossiers soumis ; part « sans déplacement physique » (objectif 70 %) ; pièces à examiner ; part de pièces refusées (seuil d'alerte 20 %).
- **Recherche** : par référence ou par nom, sans tenir compte des majuscules ni des accents (« eloise » trouve « Éloïse »), nom-prénom comme prénom-nom. Tri du plus ancien au plus récent (ordre de traitement).
- **Pagination** : 20 par page, `limit` plafonné à 100. **Filtrage et pagination se font en mémoire** sur l'ensemble des dossiers soumis (documents chargés en une requête). Largement suffisant pour une campagne (quelques milliers de dossiers) ; à passer en SQL au-delà. Noté dans le code.
- **Proxy de document** : le fichier est relu depuis le stockage interne, jamais d'URL de stockage exposée. Réponse avec le bon `Content-Type`, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: sandbox`, `Cache-Control: private, no-store`. Comme une balise `<img>` ou `<iframe>` ne peut pas envoyer l'en-tête d'authentification, l'interface récupère le fichier avec `fetch` puis l'affiche depuis une URL locale (libérée au changement de pièce).
- **Coordonnées** : la liste n'en montre pas ; le détail affiche email, téléphone, commune et département (nécessaires pour contacter ou vérifier l'identité). Aucune clé de stockage interne n'est renvoyée.
- **Écarts avec la story** : la liste vit sur `/admin` (et non `/admin/dashboard`, qui redirige) ; la page provisoire d'US-011 est supprimée. Les boutons « Valider / Refuser » et l'historique des décisions de la maquette `AdminDossier` ne sont **pas** construits : c'est US-013. Le lien « Journal d'audit » de la barre latérale est omis pour la même raison.
- **Vérifié** : `pytest` (243 tests verts, dont `test_architecture.py`) ; parcours réel (candidature complète puis, avec un jeton admin : liste, détail, proxy 200 `application/pdf`, proxy sans jeton 401) ; `tsc -b` et `vite build` sans erreur. **Non vérifié** : le rendu dans un navigateur (liste, détail, aperçu PDF et image, mobile), la recherche avec un grand volume, les pièces refusées/validées à l'écran (testées seulement via l'API).
