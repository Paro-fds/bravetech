# US-003 — Tests d'architecture en CI locale

## En tant que développeur
Je veux que `pytest tests/unit/test_architecture.py` passe automatiquement à chaque tentative de merge sur `main`
Afin qu'aucune violation de la Règle de Dépendance (Clean Architecture) ne puisse entrer dans la base de code sans être détectée.

## Contexte

`tests/unit/test_architecture.py` existe déjà dans `bravetech/tests/unit/` — il vérifie que :
- `entities/` n'importe pas `dal/`, `bll/`, `api/`, `sqlalchemy`, ni `fastapi`
- Les couches internes ne dépendent pas des couches externes

Il faut maintenant :
1. Que la structure de dossiers backend (`entities/`, `bll/`, `ports/`, `dal/`, `api/`) soit scaffoldée (même vide) pour que le test ait quelque chose à analyser
2. Qu'un workflow GitHub Actions lance `pytest tests/` à chaque PR sur `main`

Ce qu'il ne faut pas supposer déjà fait : le scaffold backend n'existe pas encore — `entities/`, `bll/`, etc. sont à créer.

## Critères d'acceptation

- [ ] La structure de dossiers backend est créée : `backend/entities/`, `backend/bll/`, `backend/ports/`, `backend/dal/`, `backend/api/v1/` (avec `__init__.py` dans chaque)
- [ ] `pytest tests/unit/test_architecture.py -v` passe en vert localement sur cette structure vide
- [ ] Un fichier `.github/workflows/ci.yml` existe et lance `pytest tests/` sur chaque push vers `main` ou PR vers `main`
- [ ] Le workflow CI passe vert sur GitHub Actions

## Hors périmètre

- Écrire du code métier dans les couches (`entities/`, `bll/`...) — les dossiers sont vides pour l'instant
- Tests d'intégration (`tests/integration/`) — couverts dans les stories suivantes
- Configuration Railway ou Vercel — reporté à US-004

## Tâches

- [ ] Lancer le skill `scaffold-backend-service` ou créer manuellement `backend/entities/__init__.py`, `backend/bll/__init__.py`, `backend/ports/__init__.py`, `backend/dal/__init__.py`, `backend/api/__init__.py`, `backend/api/v1/__init__.py`
- [ ] Vérifier que `pytest tests/unit/test_architecture.py -v` passe en vert
- [ ] Créer `.github/workflows/ci.yml` avec un job `test` : checkout → setup Python 3.11 → `pip install -r requirements.txt` → `pytest tests/`
- [ ] Pousser sur GitHub et vérifier que le workflow est vert

## Définition de terminé

- [ ] `pytest tests/unit/test_architecture.py -v` : 0 échec, 0 erreur, en local
- [ ] GitHub Actions : job `test` vert sur un push réel
- [ ] Aucun import interdit détecté (la structure vide doit déjà passer)
