# US-025: Vérifications du frontend en CI

**Status:** ✅ Done
**Milestone:** Epic 5 — Mise en production
**GitHub Issue:** [#42](https://github.com/Paro-fds/bravetech/issues/42)

---

## En tant qu'Administrateur
Je veux qu'aucune pull request ne puisse casser l'interface sans que la CI le signale
Afin que chaque fusion sur `master`, déployée automatiquement, donne un portail qui fonctionne.

## Contexte
`.github/workflows/ci.yml` (job « Architecture & Unit Tests ») ne lance que les tests Python. Le frontend (`frontend/`, React 19 + Vite + TypeScript) n'est vérifié qu'à la main : `npx tsc -b`, `npx oxlint src`, `npm test` (node --test), `npx vite build` (E5-8, [epic-005-refinement.md](epic-005-refinement.md)). Avec le déploiement continu (US-026), une erreur de build arriverait jusqu'à la VM.

Workstream : transverse (CI).

## Critères d'acceptation
- [ ] Un job frontend tourne à chaque pull request et à chaque push sur `master` : `npm ci`, `tsc -b`, `oxlint src` (avertissement = échec), `npm test`, `vite build`.
- [ ] Le cache npm est utilisé (temps du job raisonnable).
- [ ] Le job backend existant est inchangé ; les deux jobs sont requis pour fusionner (réglage de protection de `master`, à faire par le Project Owner).
- [ ] Une erreur de type ou de lint volontaire fait échouer la CI (vérifié sur une branche jetable).

## Hors périmètre
- Tests de bout en bout dans un navigateur.
- Le build des images Docker (US-026).

## Tâches
- [x] Ajouter le job `frontend` à `ci.yml` (Node 22, comme `frontend/Dockerfile`).
- [x] Vérifier que `oxlint` échoue sur un avertissement (option `--deny-warnings` ou équivalent).
- [x] Mettre à jour `PROJECT_WORKFLOW.md` (définition de fini : CI verte backend + frontend).

## Définition de terminé
- [ ] Une PR avec les deux jobs verts ; une PR de test avec une erreur volontaire, rouge.
- [ ] Le Project Owner valide → story passée à Done.

S'y ajoutent deux règles issues de l'Epic 5 : pas de mot de passe par défaut dans `docker-compose.yml` (US-023, alerte GitGuardian), et pas d'adresse réelle de la VM dans le dépôt public (US-024). « mergée sur `main` » corrigé en `master`.
