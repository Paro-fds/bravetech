# US-016: Notifications SMS en complément de l'email (simulées)

---

## En tant que candidat
Je veux recevoir une notification SMS en complément de l'email lorsqu'un document est validé ou rejeté  
Afin d'être alerté même si je consulte rarement ma boîte email.

## Contexte
Le candidat haïtien type a un accès email intermittent mais consulte régulièrement son téléphone. Un SMS de confirmation ou de rejet augmente significativement les chances que le candidat réagisse rapidement. L'implémentation suit le même pattern port/adaptateur que l'email : `ISmsProvider` avec `ConsoleSmsSender` en dev et un adaptateur réel (Twilio, Vonage ou opérateur local) si les clés sont fournies.

## Critères d'acceptation
- [ ] Un port `ISmsProvider` est défini dans `backend/ports/` avec une méthode `send_sms(to: str, message: str)`.
- [ ] Un adaptateur `ConsoleSmsSender` affiche le SMS dans les logs en développement (sans erreur si aucune clé API n'est configurée).
- [ ] Un adaptateur `TwilioSmsSender` (ou équivalent) est activé si la variable d'env `SMS_API_KEY` est présente.
- [ ] Le SMS est envoyé après une décision admin (validation ou rejet) — non-bloquant, même règle que l'email.
- [ ] Le numéro de téléphone WhatsApp saisi dans US-005 est utilisé comme destination du SMS.
- [ ] Un candidat peut désactiver les notifications SMS (champ `sms_actif` dans `candidats`, optionnel).

## Hors périmètre
- Le remplacement de l'email par le SMS (les deux coexistent).
- L'intégration avec un opérateur haïtien spécifique (dépend des clés disponibles).

## Tâches
- [ ] Définir le port `ISmsProvider` dans `backend/ports/`
- [ ] Implémenter `ConsoleSmsSender` et `TwilioSmsSender` (ou équivalent)
- [ ] Injecter `ISmsProvider` dans les use cases `ValiderDocument` et `RejeterDocument`
- [ ] Ajouter le champ `telephone` dans `candidats` si absent (sinon réutiliser champ existant)
- [ ] Écrire les tests unitaires (SMS déclenché, échec SMS non-bloquant)

## Définition de fini
- [ ] Après une décision admin, le candidat reçoit un SMS (ou log console en dev). Un échec SMS ne fait pas échouer la décision.
