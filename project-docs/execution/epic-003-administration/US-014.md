# US-014: Notification email déclenchée par une décision admin

**Status:** 🔲 Backlog  
**Milestone:** Epic 3 — Administration & Audit  
**GitHub Issue:** [#14](https://github.com/Paro-fds/bravetech/issues/14)  
**Depends on:** US-013 (Décision admin persistée), US-008 (Port IEmailSender disponible)

---

## En tant que candidat
Je veux recevoir un email immédiatement après qu'un administrateur valide ou rejette l'un de mes documents  
Afin de réagir rapidement — notamment pour remplacer un document rejeté sans perdre de temps.

## Contexte
Cette story finalise la boucle de communication entre l'administration et le candidat. L'email est déclenché dans le use case admin (`ValiderDocument` / `RejeterDocument`) via le port `IEmailSender` — le même adaptateur (ConsoleEmailSender en dev, ResendEmailSender en prod) que celui mis en place en US-008. L'envoi est **non-bloquant** : un échec email ne doit ni annuler la décision admin ni retourner une erreur HTTP à l'agent.

## Critères d'acceptation
- [ ] Après une validation admin, le candidat reçoit un email HTML indiquant le nom du document validé.
- [ ] Après un rejet admin, le candidat reçoit un email HTML indiquant le nom du document rejeté, le motif (si renseigné), et un bouton **« Remplacer le document → »** pointant vers `/suivi/{reference}`.
- [ ] Si l'envoi d'email échoue (timeout Resend, clé absente), la décision admin est tout de même enregistrée en base et l'API retourne 200 à l'agent — l'erreur est loggée côté serveur.
- [ ] En développement local sans clé Resend, le `ConsoleEmailSender` affiche l'email dans les logs serveur (aucune erreur levée).
- [ ] Les emails ne sont envoyés que si l'envoi est activé (variable d'env `EMAIL_ENABLED=true`).

## Hors périmètre
- Les notifications SMS (US-016 — Epic 4, Should Have).
- Les notifications email de soumission initiale (US-008 — déjà livré).

## Tâches
- [ ] Étendre le use case `ValiderDocument` pour appeler `IEmailSender.send_validation_notification()`
- [ ] Étendre le use case `RejeterDocument` pour appeler `IEmailSender.send_rejection_notification()` (avec motif et lien de remplacement)
- [ ] Créer les templates HTML d'email validation et rejet dans `backend/templates/emails/`
- [ ] S'assurer que les appels email sont dans un `try/except` non-bloquant avec log de l'erreur
- [ ] Écrire les tests unitaires (email déclenché après décision, échec email non-bloquant)

## Définition de fini
- [ ] Après une validation ou un rejet admin, le candidat reçoit l'email correspondant (ou le log console en dev). Un échec d'envoi email ne fait pas échouer la décision admin — la réponse HTTP reste 200.
