# US-029: Gestion des accès du personnel depuis l'espace admin

**Status:** 🔲 Backlog
**Milestone:** Epic 4 — Could Have & Should Have
**GitHub Issue:** [#66](https://github.com/Paro-fds/bravetech/issues/66)
**Depends on:** US-011 (authentification et rôles)

---

## En tant qu'Administrateur
Je veux créer les comptes de mes collègues, changer leur rôle, leur retirer l'accès et réinitialiser leur mot de passe depuis l'espace admin
Afin de ne plus dépendre d'un script lancé sur le serveur pour chaque nouvel agent.

## Contexte
US-011 ne créait que le premier compte, par `backend/scripts/seed_admin.py` lancé sur la VM ; ses notes de réalisation le signalaient : « les agents devront être ajoutés par une autre voie (US à écrire) ». `SOLUTION_DESIGN.md` §15 gardait la question ouverte. Le rôle `admin` (`get_current_admin_complet`) existait déjà.

**Story écrite après la construction.** Le code a été écrit le 2026-11-06 (commit `6b4bd88`), avant la story ; cette fiche le reconnaît plutôt que de faire croire à un Refine préalable.

## Critères d'acceptation
- [x] Seul le rôle `admin` voit le lien « Accès » et peut appeler les routes `/api/v1/admin/utilisateurs` (un agent reçoit 403).
- [x] Créer un compte `agent` ou `admin` avec un email unique et un mot de passe provisoire de 12 caractères minimum.
- [x] Changer le rôle, désactiver ou réactiver un compte ; réinitialiser son mot de passe.
- [x] Aucun compte n'est supprimé : l'historique des décisions et du calendrier reste attribué.
- [x] Un administrateur ne peut ni se désactiver ni se retirer le rôle `admin` ; le dernier administrateur actif est protégé.
- [x] Un compte désactivé est refusé dès sa requête suivante.

## Hors périmètre
- Envoi du mot de passe provisoire par email ; changement de mot de passe par l'intéressé lui-même.
- Synchronisation avec FDS SYS.

## Tâches
- [x] Cas d'utilisation `backend/bll/gerer_utilisateurs.py`, port et adaptateur étendus.
- [x] Routes `GET`/`POST /admin/utilisateurs`, `PATCH /admin/utilisateurs/{id}`, `PUT /admin/utilisateurs/{id}/mot-de-passe`.
- [x] Page `pages/admin-utilisateurs`, lien « Accès ».
- [x] Tests d'intégration `tests/integration/test_utilisateurs_api.py`.
- [x] Specs ws-func-04 §5, ws-tech-04 §5 ; glossaire (Agent, FDS SYS).

## Définition de terminé
- [ ] Sur la VM : l'admin crée un compte agent, l'agent se connecte, voit les dossiers mais pas « Accès » ni la modification du calendrier ; l'admin le désactive, l'agent est déconnecté à la requête suivante.
- [ ] Le Project Owner valide → story passée à Done.
