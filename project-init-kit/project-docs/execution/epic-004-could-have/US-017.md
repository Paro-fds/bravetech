# US-017: Mode sombre interface admin et formulaire candidat

**Status:** 🔲 Backlog  
**Milestone:** Epic 4 — Could Have & Should Have  
**GitHub Issue:** [#17](https://github.com/Paro-fds/bravetech/issues/17)  
**Depends on:** Epic 3 terminé (interface admin stable)  
**Priorité MoSCoW:** 🔵 Could Have

---

## En tant que candidat / administrateur FDS
Je veux pouvoir basculer l'interface en mode sombre  
Afin de réduire la fatigue visuelle lors d'une utilisation prolongée, en particulier sur mobile.

## Critères d'acceptation
- [ ] Un bouton de basculement (icône soleil/lune) est accessible depuis la barre de navigation principale et depuis le dashboard admin.
- [ ] Le thème (clair/sombre) est persisté dans `localStorage` et restauré au rechargement de la page.
- [ ] Le mode sombre est implémenté via `[data-theme="dark"]` sur la balise `<html>`, sans librairie externe.
- [ ] Toutes les couleurs de l'interface utilisent des variables CSS centralisées — le changement de thème ne nécessite aucune modification de composant.
- [ ] Les contrastes du mode sombre respectent WCAG 2.1 AA (ratio ≥ 4.5:1 pour le texte normal).
- [ ] La préférence système (`prefers-color-scheme`) est détectée au premier chargement si aucune préférence n'est enregistrée.

## Hors périmètre
- Thème personnalisable (couleurs custom) — hors MVP.
- Mode sombre sur les emails transactionnels.

## Tâches
- [ ] Définir les variables CSS pour les deux thèmes dans `index.css` (couleurs, surfaces, textes)
- [ ] Implémenter le hook `useTheme()` pour gérer la persistance `localStorage`
- [ ] Ajouter le bouton de basculement dans le composant `Navbar` et le `AdminLayout`
- [ ] Tester les contrastes sur les pages critiques (formulaire candidature, dashboard admin, page suivi)

## Définition de fini
- [ ] Le basculement clair/sombre fonctionne sur toutes les pages. Le thème est mémorisé entre les sessions. Les contrastes WCAG AA sont respectés en mode sombre.
